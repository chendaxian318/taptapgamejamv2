店员 / Shop_Assistant — 站立对话资产
制作日期：2026-10-16

交付用途
按当前项目的固定站位商店角色需求准备，身份保留 Shop_Assistant / 店员。
成品脚底中心为原点，glTF / Unity 坐标 +Y 向上、+Z 正面，总高 1.6 米（包含背部最高道具）。
原始模型仅进行整体旋转、平移和等比缩放；原始几何形状、30,821 三角面、UV、原贴图保留。

文件
Shop_Assistant_Rigged.glb：20 骨骼、3 动作、完整内嵌 PBR 贴图。
Shop_Assistant_Rigged.blend：Blender 5.2.2 LTS 工程，贴图已打包，可编辑骨架、权重和 Action。
Shop_Assistant_Rigged.fbx：通用 DCC / Unity 导入版，基础色内嵌；原始两张贴图另外放在 textures 中。
MetallicRoughness 贴图 G 通道为粗糙度，B 通道为金属度；FBX 材质转换不完整保留 glTF 打包语义，须在目标引擎按通道配置。不要把原粗糙度直接当成 URP Smoothness。

动作（源工程 30 FPS）
Idle：4 秒，0–120 帧，循环。极轻微头部与上身活动。
Talk：3 秒，0–90 帧，循环。低幅度点头及朝向变化，无口型与面部形变。
Greet：2 秒，0–60 帧，单次。礼貌点头与轻微上身致意，结束回到中性姿态。
三动作都保持根节点与脚底稳定，不包含 Root Motion；手臂维持持物姿势，不做挥手或抬手。
动画以秒储存。导入软件 FPS 不同，帧数会换算，时长不变。FBX Action 名可能带骨架名前缀。
Unity 可使用 Generic、Apply Root Motion 关闭，仅 Idle/Talk 开启 Loop Time。

当前验证范围
当前模型是闭合手套、宽大衣袍、背包和抄网融合成的单一网格；动作针对站立 NPC 的轻幅对话用途制作。
20 骨保留后续美术编辑结构；本轮没有验证走跑、通用 Humanoid 重定向或大幅四肢动作。未来若需要抬手挥手/行走，应另做权重与融合衣摆处理。
背包及抄网的刚性主体保持稳定，背包与衣服连接处存在柔和权重过渡。没有添加口型、眨眼、手指或交易递物动画。

真实开源流程
UniRig 官方仓库：https://github.com/VAST-AI-Research/UniRig
本地代码提交：6793c6640ff01c8fb389f3993434124bb43d2933，代码 MIT 许可证附在 evidence。
实际运行 skeleton checkpoint、seed 12345，得到 34 骨原始结果。
自动结果把部分兜帽/杂物识别成头部分支，并对闭合手套生成不可靠指骨。按真实多视图与实际肩胯/脚的位置校正成 20 骨，加入背包和抄网控制骨。
随后实际运行 skin checkpoint，得到 32,768 采样点蒙皮；进行最近邻重采样、焊接位置上的温和平滑、宽带身体区域约束、脚底与硬质道具约束，并限制每点最多 4 权重。
动作在 Blender 中制作。初版抬手造成融合衣摆拉扯，最终按项目用途收敛到稳定站立点头动作。
因此交付是 UniRig 推理后人工规则校正与动画制作的结果，不是未经修改的原始 AI 自动结果。
原始骨架、原始蒙皮、校正骨架、NPZ、日志与制作脚本保留以供复核。

复核摘要
GLB 和 FBX 均重新导入 Blender，逐动作采样 17 帧；时长正确、首尾一致，没有新增退化面或三角法线转向超过 90 度。
原几何扣除声明的整体变换后最大位置误差约 6.63e-8 米，UV 误差为 0，全部三角形对应及绕序保留，原贴图哈希相同。
GLB 导出有 35,234 顶点（源为 35,211；多 23 个为属性拆点，不改变形状/三角面）。10,926 组同位置顶点权重一致。
脚底漂移小于 0.0000018 米；抄网刚性误差小于 0.0000002 米，背包主体小于 0.0000004 米。
preview 的 GIF 与多视图图片均由最终模型真实渲染。

项目接入边界
本轮只完成资源归档与必要骨架动画，没有改动 Unity 项目、Prefab、场景、碰撞或玩法。
当前项目商店角色加载器没有 Talk/Greet 动画触发接口；未来接入需配置 Animator 并由显示层在对话开关时切换状态，不能视为本轮已经在游戏里触发。

复现
production 内有 run_shop_assistant.ps1，可分 extract/skeleton/refine/skin/weights/build 运行。
脚本使用当前电脑的原始下载路径、UniRig 仓库、env.ps1 与 Blender 路径；迁移电脑或路径时需相应调整。
所有输出以当前脚本目录为工作根；不会自动修改 Unity 工程。
