一、项目当前状态

这是依据 FigJam 策划案制作的 Unity 3D 玩法测试原型，用于验证地形改造、动物栖居、繁衍、机关与交易。当前使用 Unity 6000.6.0f1、URP 17.6.0、Input System 1.20.0，GLB 原生导入使用 glTFast 6.20.0；准确依赖以 ProjectSettings/ProjectVersion.txt、Packages/manifest.json 和 Packages/packages-lock.json 为准。

主场景：Assets/HabitatIsland/Scenes/HabitatIsland.unity。
主程序：Assets/HabitatIsland/Scripts/HabitatGame.cs。
默认 startLevel=4，对应菜单第 5 项“Figma · 荒岛关卡”，不是旧第 4 关生态沙盒。场景序列化值及代码默认值都为 4，进入后暂停。棋盘、角色显示与 HUD 主要在运行时创建，不能只根据编辑状态下的场景层级判断内容是否缺失。

正式关是一张 18×19 的连续图，共 342 格，由 FigJam 四张表拼接。用户已确认数字表示地面高度，道具放在该高度上。原图坐标从左上开始，向右列号增加、向下行号增加；世界坐标 x=列，z=18−行。原图 0 基坐标和观察卡“原图几行几列”的 1 基坐标要区分。

初始动物为虾 1、鱼 2、寄居蟹 1；图中没有水母、海龟、海星的初始位置。道具共箱子 5、浮块 4、攀爬块 1、潮汐引擎 1、障碍 2、宝箱 2。初始贝币、货物、虾笼为 0，无鱼竿。鱼竿由原图宝箱获得。旧四个 9×9 实验关仍保留，供规则回归，不替代当前正式关。

默认相机正交，yaw=0°、pitch=58°，局部 orthographicSize=6.5。全图缩放按地图和视口计算，1920×1080 的既有记录约为 13.04885。移动方向跟随镜头，不固定于棋盘世界坐标；直接调用 Move(dx,dz) 时仍使用棋盘坐标。

当前主要操作：
WASD／方向键：按画面上下左右移动；迎着箱子走可推箱。
Shift+方向：攀上箱子／攀爬方块；不是冲刺键。
左键：选格。E／右键：执行当前工具，右键同时选格。
1～5：搬运交互、铺土、钓竿引导、虾笼、收获／垂钓。
R：旋转相邻道路或风机。
Space：暂停／继续；英文句号：暂停并推进 1 秒；Z：撤销；Backspace：重开。
M：全图；Home：回到人物局部跟随；中键拖动：平移；滚轮：缩放；Q／C：每次旋转 90°。
Tab：实验室；B：补给商店；F1：帮助；Esc：关面板或取消垂钓。
垂钓时按住 Space／左键抬升捕获区域，松开下落；取消／失败保留后代，成功收取后代并保留亲代。垂钓期间岛屿模拟暂停。

二、用户约束与工作口径

1. 优先完成用户当前明确提出的工作。非必要不改核心规则；美术、镜头、材质或动画调整应尽量只改显示层。确需改规则时同步来源／假设文档，并执行有针对性的回归检查。
2. 保持正式图逐格对应及用户确认的高度含义。未定义的奖励、角色、地图格或终局不能自行补成策划事实；源数据与运行时取值要分开记录。
3. 用户要求使用合适的素材，不能为了已有文件而硬套旧版美术。优先保留已认可的模型、清晰俯视角和可读 HUD；旧原画、旧 AI 主角与完整海港图不是必须恢复的目标。
4. 最新虾按用户选择静态接入。未执行 UniRig，也没有为虾新增骨骼或动作动画。不要自行追加模型上传、重生成或绑定流程。
5. 日常迭代先在 Unity 编辑器内验证。用户未明确要求时，不重新构建 EXE；本次工程交接不等于要求生成新的游戏发行包。
6. 不把历史检查写成本轮全部重测通过，不把局部路线通过写成完整通关。先查看 Verification 报告的范围和时间，再报告结果。

五、已知限制与需策划确认的内容

正式图最终委托未定义，没有自动胜利条件。当前检查点只记录潮汐、宝箱鱼竿、开箱数和寄居蟹是否受惊移动；不能用“两个箱子都开了”推导通关。

原图的两格黄色船标记未说明船下高度，运行时按水格 0 处理；无数字的末端宝箱暂取地面高度 1；出生点取原图 (3,8)。这些是明列的实现取值，不是源图原文。末端宝箱奖励未标明，当前只记录开箱，不凭空给奖励。

方向惊吓：正式图中虾主动移动到四向相邻后，符合高度、合法退路与庇护条件的动物沿远离虾的方向退一格；正后方被挡就停留，不能随机绕行。被抱放下、风机被动载移、虾静止不属于同一种主动接近事件。旧实验关保留旧邻近威胁逻辑，修改时注意两套入口。

已核对路线到达寄居蟹岛，未完成验证末端宝箱全程、鱼竿后的繁衍—垂钓—交易—购买风机完整经济循环。原图仅有鱼、虾、蟹，虾不计入蟹的友好多样性，不能直接套旧实验关“两种友好物种”条件宣称完成委托。

价格、繁衍时间、行动节奏、钓鱼难度属于可调测试值。虾笼保留亲代并使其停留，可重复收取后代；与源案一次性消耗品的口径尚有简化。剧情、居民对话、独立航行地图与长期成长尚未实现。

主角只有三段移动动画已接线；虾是静态模型加显示移动／转身，不是完整生物动画。仍有原画与几何占位并存。3D 虾含两张 4K 图及约 3 万面，若出现性能压力先测量，再考虑导入压缩、尺寸或 LOD，不改动物判定来掩盖显示性能问题。

六、后续开发建议

1. 新电脑恢复工程后，先确认主场景进入正式图且暂停，检查主角、虾、材质、中文、选格、镜头和搬运。记录新环境实测结果，再开展功能修改；迁移先看 00_换电脑先看这里.txt，工具接入按 Docs/工具连接与验证.txt 操作。
2. 开始关卡扩展前，优先向策划补齐最终委托、末端宝箱奖励和完整经济通路；保留源图／实现假设的区别。
3. 按用户下一项要求小步推进。纯美术变化优先改 View、Visual、材质或对应预制体；仅在确需改变行为时进入 HabitatModel，并同步文档。
4. 若用户要求互动动画，再将现有主角动作接到明确的玩法事件；虾后续是否绑定骨骼应重新按用户选择处理。当前无需 UniRig 才能继续开发或测试。
5. 修改输入、镜头或 HUD 后关注旋转方向、不同宽高比、面板挡点击；修改动物模型后关注脚底、水面高度、携带锚点、转向和状态条遮挡；修改地图后对照 level-grid.json 并复验可达路线。
6. 有新结果时更新对应说明，注明实际执行范围。不要自动覆盖源素材、重做已认可 UI，也不要未经本轮请求重建 EXE。
