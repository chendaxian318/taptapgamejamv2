## 目标与规则口径

`70:3472` 的寄居蟹委托要求“帮助它交到更多的朋友”，但没有量化人数、物种或最终通关状态。`75:3482` 红虾说明以逗号结尾，语句尚未写完。两个宝箱不能直接推导为“两箱全开即通关”，也不能套用旧实验关的六物种繁衍通关条件。

`92:1921` 新写明的惊吓规则用于本轮重点核对：大虾**主动移动到上下左右相邻格时**，动物立即沿远离大虾的方向移动 1 格；正后方被挡则原地不动，不能随机逃跑。图中 `80:3512` 提示玩家可以放置吹风机改变方向，但没有初始风机格；当前没有额外添加初始风机。

## 当前实现选择

以下用于形成可运行的测试版本，均不改写源图数据。

| 项目 | 当前实现 | 原图边界 |
|---|---|---|
| 地面与道具 | 数字作为地面高度；箱子、攀爬方块另增加一层可站立表面 | 数字表示地面高度、道具叠放其上已由用户确认；道具自身高度沿用现有机制 |
| 黄色船格 | `(2,8)`、`(2,9)` 在运行地图按高度 0 水格处理；码头连接右侧陆地 | 源 JSON 仍保留 `height: null`，不将黄色直接说成已标注水格 |
| 出生位置 | 源图 `(3,8)`，即世界 `(3,10)`，从船右侧陆地开始 | 原图没有玩家出生标记 |
| 末端宝箱 | 地面高度暂取 1；打开只计数，不给未注明的奖励 | 源 JSON 高度、奖励仍为空 |
| 鱼竿宝箱 | 打开 `(12,4)` 宝箱取得鱼竿，不额外给金币，不能重复领取 | 鱼竿奖励在图上明确写出 |
| 初始库存 | 贝币、货物、虾笼均为 0，没有鱼竿 | 属于测试开局取值 |
| 小鱼 | 两只使用现有金鱼行为与垂钓流程 | 源图只写“小鱼” |
| 方向惊吓 | 虾主动跨格后首次进入四向相邻时触发；同表面高度、退路合法且无庇护时沿相反方向退一格 | 与旧高度、庇护、栖息地规则的组合为本轮实现口径 |
| 被动靠近 | 放下红虾、风机载着红虾移动、红虾静止不算主动接近；堵路不横向绕行 | 对“主动靠近”的操作定义 |
| 检查点 | 记录潮汐是否触发、是否由宝箱取得鱼竿、开箱数及蟹是否受惊移动 | 检查点不代表通关；最终委托条件未定义，当前没有自动胜利判定 |

正式图与旧实验关的惊吓逻辑分开：新图使用主动接近事件，旧关保留原来的邻近威胁移动，便于回归对照。

## 编辑器启动与当前操作

打开 `Assets/HabitatIsland/Scenes/HabitatIsland.unity` 后 Play。场景 `startLevel=4` 是代码中的第 5 个选项“Figma · 荒岛关卡”，不是旧第 4 关沙盒。开局暂停，移动和工具仍可操作；按 Space 恢复模拟观察动物。

此前布局验证曾将编辑器留在正式图、暂停、全图视角；这不是迁移后应依赖的编辑器状态。右下角提供“全图”和“回到人物”按钮，重新进入 Play 时默认使用人物附近的局部视角。

| 操作 | 输入 |

| 移动／推箱 | WASD／方向键，方向跟随镜头，按画面上下左右移动 |
| 攀上箱子或攀爬方块 | 按住 Shift 再按方向键；当前允许目标表面向上最多两层 |
| 选格／执行工具 | 左键选格，E 使用；右键选中并使用 |
| 搬运与开箱／铺土／引导／虾笼／收获垂钓 | 1／2／3／4／5 |
| 暂停／单步／撤销／重开 | Space／`.`／Z／Backspace |

默认镜头 yaw 0°、俯角 58°，局部正交尺寸 6.5；本次 1920×1080 全图视图测得正交尺寸约 13.04885，由地图边界和界面留白计算。Home 不强制清除已旋转的朝向。最新[局部画面](../Verification/figma-level-local.png)与[全图画面](../Verification/figma-level-overview.png)均为 1920×1080，已检查右下镜头按钮与包含原图坐标的地块详情，文字无截断。

已验证路线为：从默认出生点到潮汐箱，推箱涨水并撤销复验，取走压板箱子退潮，再到原图宝箱取得鱼竿，搬运原有浮块填过一格水隙，抵达寄居蟹岛。路线通过实际规则／控制器调用完成，未直接赋值玩家位置，未发放额外资源，动物模拟保持暂停；控制器检查还验证了保存读取、保护已有最新存档，以及结束时恢复正式图开局暂停状态。两份报告中的路线坐标是**世界 `(x,z)`**，对应源图 `(列,18−z)`。

该路线也确认两个设计约束：潮汐压板持续受压时，高度 1 的连接地面被淹，不能只靠步行前往鱼竿宝箱；寄居蟹岛和末端宝箱岛开局不能只靠步行／攀爬抵达，需要浮块或箱桥。

**尚未验证**：末端宝箱的完整到达路线、取得鱼竿后的繁衍—垂钓—交易—购买风机完整经济循环，以及未定义的任务终局。原图只有鱼、虾、蟹三种动物，鱼只提供一种友好物种，虾不计入蟹的繁衍多样性，因此不能套用旧“两种友好物种”目标宣称完成。本轮结果是布局一致、上述可达路线及显示输入检查通过，不是全关通关结论。

以下保留为策划手动复验清单：

1. **逐格布局**：进入正式地图，与 JSON 对照 342 格及上表对象位置。记录坐标转换、出生点、船格处理、无数字宝箱高度等实现取值；检查海拔数字是否仍表示地面高度。
2. **方向惊吓**：让红虾主动靠近同层动物，检查只退 1 格且方向正好相反；挡住退路后应停留，不能横向绕路。虾不移动时单步推进、或动物自行靠近虾，不应被当成一次新的虾主动接近。另记录高差与水陆边界的处理。
3. **机关与攀爬**：分别试推箱和 Shift 攀爬；推动潮汐机关旁箱子触发涨水，检查水面、浮块和乘客位置；撤销应恢复。攀爬与推动应可由玩家明确区分。
4. **宝箱和垂钓**：到 `(12,4)` 交互取得鱼竿，再次交互不能重复奖励；取得鱼竿后测试两只小鱼的垂钓流程。末端宝箱只按已确认的实现处理，不自行补奖励或触发最终通关。
5. **大地图查看**：试 M 总览、Home 镜头归位、中键平移、滚轮缩放和 Q／C 90° 旋转。确认全图可看清，选格与实际目标一致，点击面板不会误操作岛上对象。
6. **复现与记录**：对照保存时的快照，检查读取后的布局、动物、宝箱领取状态、库存、参数及操作计数一致。存档不保存当前工具、镜头、模拟速度或撤销栈；读取后会清空撤销历史并暂停，不应要求这些未保存的界面状态恢复。存档位于 `Application.persistentDataPath/Playtests`，迁移某次实验需单独复制对应 JSON。记录验证时间、项目版本与实际操作结果。

策划可据此复验手感并补充末端路线、经济循环及委托定义；未跑过的项目保持待验证。本次迁移仅做源码归档，不生成或更新 Windows 包。
