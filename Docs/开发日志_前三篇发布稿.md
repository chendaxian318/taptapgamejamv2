# 海岛项目 Game Jam 开发日志前三篇发布稿

当前已积累的开发内容整理为以下三篇，采用正式的 Game Jam 项目记录口吻，可按一天一篇发布。第四、第五篇留给后续几天的新进展，届时依据实际完成内容续写。以下正文沿用上一版已核对的项目记录，篇次表示发布顺序，不代表工作发生在三个连续自然日内。

## 开发日志 01 从策划案与生态规则到海岛关卡

本次 Game Jam 项目围绕海岛环境中的空间解谜与生物栖居展开。玩家需要观察地形和生物之间的关系，通过搬运、调整地形和使用机关，改变岛上的通路与生活条件。我们希望每次操作都能带来可以观察的变化，例如一块新增的陆地既能连接道路，也可能改变附近生物的活动范围。

策划案将“收集素材、改造地形、引导动物到合适的栖居地”作为主要行动，并规划通过捕捞、码头交易和购买地块支持下一轮改造。寄居蟹“交到更多朋友”的委托，为生态关系提供了具体的关卡动机：玩家需要考虑怎样让其他生物靠近它、怎样改善周围环境。目前这条委托的最终完成条件仍在讨论，完整的收获与改造循环也需要继续验证。

开发初期，我们先将策划中的生态关系整理为能够运行和验证的规则。原型包含水母、红虾、金鱼、寄居蟹、海龟和海星六类生物，它们对水域、岸地、高地和邻居有不同要求。金鱼需要足够大的封闭池塘，寄居蟹关注周围的物种多样性，海龟的高地家园则与庇护效果有关。这些差异为地形改造提供了具体目的。

把文字规则转成程序时，需要先明确“连通”“附近”和“同一高度”等概念的判定方式。我们逐项记录这些边界，把尚未确定的数值保留为可调整的测试参数，并在 Unity 中搭建了四组小型规则实验场。暂停、单步推进、撤销和状态记录功能也在这一阶段加入，方便观察和复现一次操作带来的结果。

随后，我们将 FigJam 中的四张关卡表格拼接为一张 18×19 的连续地图，共 342 个格子，并逐格核对地面高度、道具位置与生物分布。地图中的数字统一表示地面高度，道具再放置在地面之上。这张正式地图目前围绕红虾、小鱼和寄居蟹展开，六物种实验场继续用于独立检查生态规则。

![FigJam 关卡策划表局部](D:/chatgptproject/taptapgamejam/HabitatIsland3D/Docs/SourceEvidence/LevelDesign/62-3067.png)

*关卡策划表局部：以颜色区分水域和陆地，在格子内记录高度、生物与机关位置，作为场景搭建和逐格核对的依据。*

关卡的空间变化主要来自箱子、漂浮块与潮汐机关。箱子压住机关后，水位上升，低地可能被淹没，漂浮块也会随水面抬升。搬运机制已包含推动、后拉和水中浮箱回收，每次动作都需要检查物体目标位置与玩家落点。正式关中的红虾主动靠近同层动物时，还会触发沿相反方向退一格的反应；退路被挡住时，目标停留原地。地形、道具和生物因此能够共同参与路线设计。

阶段验证已覆盖触发与解除潮汐、取得鱼竿，以及利用原有浮块抵达寄居蟹岛等路线。末端宝箱路线、完整捕捞交易循环和最终委托条件仍需完善，最新攀爬规则调整也需要重新验证相关路线。后续关卡工作将继续检查机制之间的配合，让玩家能够通过观察与尝试理解规则，并逐步接近目标。

## 开发日志 02 整理美术素材并接入角色与码头

前期美术草案已覆盖主角正背面、生物造型、水面纹理，以及港口房屋和小船等场景元素。主角原画以宽檐帽、披肩和胸前提灯形成鲜明轮廓，青绿、赭黄与米白构成主要配色；生物草案则通过蓝色水母、橙红色虾和金黄色鱼形成色彩区分。这些素材为角色识别和场景配色提供了具体参考。

![主角早期正面原画](D:/chatgptproject/taptapgamejam/HabitatIsland3D/Assets/HabitatIsland/Resources/Art/Artist/HeroFront.png)

*主角早期正面原画，保留了造型批注与配色参考。当前游戏主角已使用三维模型。*

![生物造型与配色草案](D:/chatgptproject/taptapgamejam/HabitatIsland3D/Assets/HabitatIsland/Resources/Art/Artist/Creatures.jpg)

*生物草案中的多种造型探索，用于记录前期美术方向；其中红虾已在后续版本中接入三维动画模型。*

在关卡与基础交互能够运行之后，我们分阶段接入原画与三维资源。主角使用已提供的 Meshy 旅行者模型，接入待机、行走和跑步动画；红虾加入待机、移动和被抱起三种动作；虾笼的笼门与浮漂根据捕获和取出状态变化。地形选用 KayKit 的圆角草地、泥土和沙地方块，外围棕榈与石块使用 Kenney 资源，与项目已有素材共同搭建测试场景。水母、金鱼等仍保留原画表现，海龟和海星暂用几何造型，整体美术还在逐步统一。

模型接入需要同时处理比例、朝向、贴地位置和携带位置。比如红虾在地面上的尺寸需要足够醒目，被抱起后又不能大面积遮住主角；虾笼的动作需要与捕获状态对应，撤销或重建场景时也要恢复正确外观。我们围绕这些状态逐项检查，减少模型表现与规则结果之间的偏差。

码头接入过程中出现了一个直接影响体验的问题：完整模型虽然已经放在岛边，角色仍受原有格子边界限制，无法真正走上平台。为此，我们调整了码头尺寸和连接木桥，并根据模型的甲板、建筑及障碍位置重新设置可行走区域。主角进入码头后采用连续移动，脚底跟随甲板高度，返回岸边时恢复格子操作。

目前，主地图中的岛屿与码头已经能够直接步行往返，商店也接入了近距离交互。往返时还需要保持携带物品、镜头朝向和角色状态一致，避免玩家走到码头后丢失原有操作状态。码头因此具备了实际使用的空间，能够承接岛屿探索中的返回与补给需求。

另行搭建的码头流程原型，以家、商店和小船作为主要交互点。我们通过 Timeline 串联海鸟掠过、主角返航收网、带着渔获前往商店等片段；交付后回家休息，再用窗边晨光表现进入第二天。这些片段用于检验行动顺序、镜头衔接和自由操作之间的切换。

这一阶段打通了码头通行，并搭建了返航与次日流程。码头原型中的渔获交付目前仍属于剧情状态，尚未与岛屿库存形成完整经济结算。接下来会继续衔接捕捞、回港和补给，同时根据试玩反馈调整角色动作，让场景流程和实际操作更连贯。

## 开发日志 03 优化场景表现并梳理试玩反馈

随着模型和场景逐渐完整，画面能否准确传达规则成为本阶段的重点。玩家需要看清主角位置、地块高低差和交互物体的轮廓。我们调整了镜头俯角和侧向角度，使人物正面与地形侧面更容易观察，同时保留镜头旋转后按画面方向移动的操作方式。

场景美术方面，前期港口拆件图包含青绿色木屋、暖色木构件、盆栽、围栏与小船，提供了码头生活空间的视觉参考。水面沿用已有手绘纹理，并在显示时减弱笔触对地格的干扰；界面经过多套方案比较后，采用纸白面板、深海绿文字和少量珊瑚色强调。原画、场景与界面的颜色因此有了共同参考，细节表现也需要服从玩家观察道路和生物的需求。

![前期港口场景拆件图](D:/chatgptproject/taptapgamejam/HabitatIsland3D/Assets/HabitatIsland/Resources/Art/Artist/HarborParts.png)

[单独打开场景拆件图原图](D:/chatgptproject/taptapgamejam/HabitatIsland3D/Assets/HabitatIsland/Resources/Art/Artist/HarborParts.png)

*前期港口拆件素材，包含房屋、小船、围栏和绿植。当前可行走码头使用后续接入的完整三维模型。*

早期遮挡处理会把前方高地大幅淡化，虽然露出了后方区域，却让整片地形接近透明，攀爬方块的梯子也不够醒目。调整后，普通地块保持实心，只在挡住主角或当前选中位置时轻微淡化；攀爬方块的主体、草顶和梯子保持清晰显示。我们希望玩家既能找到角色，也能准确判断地形厚度和可用落点。

码头贴图的清晰度来自另一类限制：房屋、木板、小船和植物共用一张贴图，模型放大后，局部纹理细节不足。我们将码头颜色贴图由 4K 超分到 8K，并在相同机位下检查处理效果。改善主要体现在木板缝和屋顶图案的边缘，原素材中已经模糊的细节仍需后续精修。根据场景反馈，大屋前的一段楼梯也已移除，木平台补面、木纹衔接、碰撞和行走边界同步更新。

界面方面，前期完成了不同窗口比例的布局适配，以及弹窗阻止场景误操作等处理。项目也已制作过 Windows 测试包。随着实际操作增多，新的反馈开始集中在移动手感、动作表现和流程引导上，说明后续需要把已有内容进一步整理成连贯的游玩体验。

其中，人物动画与逻辑位置不同步是需要优先处理的问题：画面中的角色还没走到目标格，程序就已经判定到达，导致后续交互可能提前发生。下一轮将围绕移动完成时机、连续输入和途中交互进行修正，并结合降低移动速度、专门的推箱动作和掉落表现，检查角色动作与规则反馈是否一致。

其他反馈包括调整主角比例、开局空手、只有可攀爬方块允许攀爬、登船后进入地图选择，以及打捞通过黑屏转场将方块放到指定位置。底部界面和生物头顶信息也将进一步精简。这些内容仍需完成后逐项验证，攀爬变化涉及的关卡路线也需要复测。后续开发记录将继续跟进实际修改与测试结果，重点检查操作反馈、流程衔接和关卡目标是否清楚。
