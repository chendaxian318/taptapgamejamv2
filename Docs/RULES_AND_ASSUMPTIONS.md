# 策划来源与原型取舍

来源：[FigJam 策划案](https://www.figma.com/board/6xPhvAzHpPDO9pjqsH6eSC/Untitled?node-id=81-3569)。读取日期：2026-10-12。六物种规则以指定分组 `81:3569` 为准；其他位置用于补充操作、机关和经济循环。

这是供策划验证生态关系与空间解谜的测试原型。以下“原文规则”与“原型取舍”分别记录，便于讨论时区分复现问题和仍待设计的问题。

2026-10-13 已新增按四张 FigJam 表格拼接的正式图，默认载入“Figma · 荒岛关卡”。该图的坐标、主动接近惊吓、宝箱、攀爬与未定义委托见 [正式关实现记录](FIGMA_LEVEL_TEST.md)。下文旧四关的通关目标、初始资源与邻近逃跑口径仅用于实验关回归，不自动套用正式图。本轮只进行 Unity 编辑器验证，不安排打包。

## 六物种规则快照

## 当前测试口径

以下是实现为可计算规则时采用的暂定定义，不是策划案新增原文。范围与阈值均按默认参数描述；参数面板可实时调整红虾／友好半径，以及水域、池塘和高地格数。

| 项目 | 本轮取值或判定 |
|---|---|
| 连通 | 四方向连通，不计对角接触；陆地可达路径每步落差不超过 1 层。 |
| 3×3 邻域 | 以动物所在格为中心，含对角；范围内其他物种不要求与中心同高度。 |
| 水格 | 表面高度不高于当前水位；浮箱所在格按可站立表面处理。 |
| 封闭池塘 | 连通水域未触碰棋盘边界；棋盘边界视为与外海相连。 |
| 高地 | 高度至少为 2，且高于当前水位。 |
| 海龟中心 | 海龟放下时设定中心，可搬运迁居；在中心 3×3 内活动。 |
| 海龟庇护 | 高地家园有效时围绕中心覆盖 3×3；目标或红虾处于庇护范围就抑制该次驱赶。 |
| 寄居蟹 | 补充采用陆生设定；多样性不计自身与红虾；通常静止，受惊后移动。 |
| 海星友好 | 本轮计入寄居蟹与水母。 |
| 繁衍 | 默认持续适居 18 秒产生 1 个后代；失去适居条件或被抱起时进度归零。后代以数量表示，不额外占格。 |
| 行动节奏 | 默认基础间隔 2.5 秒；海龟、海星为其 2 倍。 |
| 通关 | 旧实验关：目标物种均至少繁衍过一次，且每个目标物种当前至少有一只处于适居状态；完成后可继续测试。正式图的最终委托未定义，只有检查点记录，不触发自动胜利。 |
| 拿取动物 | 红虾、水母、海龟可拿取；金鱼仅通过水路引导；寄居蟹、海星不能拿取。 |
| 水母移动 | 在连通水格中活动，优先选择更靠近海星的合法格。 |
| 道路引导 | 旧实验关中寄居蟹受惊后从合法逃离方向中选择，道路朝向参与同距离候选的优先选择。正式图只沿红虾相反方向退一格，不随机改道。 |
| 铺土与攀高 | 可在周围 3×3 空格填土，最高 3 层，放置后不超过玩家表面 1 层。2026-10-15 晚间最新确认覆盖此前规则：普通表面和木箱禁止向上攀爬，即使只高一层；仅 ClimbBlock 可用 Shift + 方向键向上攀高至多 2 层。同高行走与落向合法干燥表面允许。 |
| 后拉与捞箱 | Ctrl + 背离箱子的方向键，沿平地或下坡后拉，箱子移到原站位。相邻水中或低处箱子改为黑屏打捞：箱子放到玩家原格，玩家向反方向退一格，全程空手。E 搬运与 Ctrl 后拉遇到此类目标均走黑屏流程；原格须空、干燥，退路须同高或更低、干燥、无阻挡，并预验潮汐变化。浮箱上岸成为木箱，ClimbBlock 类型保持；不能捞起脚下支撑箱。 |
| 移动同步 | 普通步行 2.5 格/秒，推拉 1.5 格/秒。先预演目标，人物及被推拉箱子全部实际到位、落地动作完成后才更新逻辑位置并记录一次撤销；途中冻结生态 Tick 和会改状态的输入。黑屏打捞在完全变黑时提交一次，渐明完毕再接受操作。 |
| 虾笼 | 自动收集该格虾的后代并保留亲代；为便于测试，同时使亲代停留。放置消耗库存，但格上的笼可重复捕获；尚未采用原案的一次性消耗逻辑。 |
| 金鱼垂钓 | 有鱼竿且距离不超过 4 格时，以工具 5 开始。按住 Space／左键抬升捕获区域，松开下落；覆盖鱼标记积累进度，进度满时收取目标后代。进度归零或超过 35 秒失败，Esc 可取消；失败／取消不扣后代，亲代始终保留。 |
| 风机 | 最远沿直线检查 5 格，推动遇到的首个浮箱；搭乘者随浮箱移动。 |
| 交易测试值 | 金鱼后代 8、虾后代 5；土壤 5、箱子 6、浮箱 7、风机 10、潮汐引擎 12、钓竿 10、虾笼 3 贝币。船上初始土壤先免费领取。道路代码价格为 3，但当前商店界面未上架。 |

其余物种的后代作为研究记录，交互收取提供每只 2 贝币的测试奖励。该奖励用于让策划快速实验，不代表正式经济设计。

## 需要保留讨论空间的定义

策划尚未明确以下边界，测试时应关注它们是否符合预期：

- 连通是否包含斜角；可达范围允许多高的落差；红虾威胁半径，以及高度按地面还是水面计算。
- “封闭池塘”的边界判定；“高地”的绝对高度或相对水位；海龟中心是否可以迁移、是否可抱起。
- 海龟庇护是否保护所有被驱赶物种，或只保护寄居蟹、海星；庇护范围是否跟随海龟或围绕高地中心。
- 海星的友好物种是否只含寄居蟹，或也含被它吸引的水母、提供保护的海龟。
- 寄居蟹繁衍多样性是否计入红虾；安全是否是所有物种繁衍的附加条件。
- 繁衍耗时、移动间隔、失败后繁衍进度的保留方式、价格和收益。
- 关卡完成是所有动物同时适居，还是指定物种各有一只适居；完成后是否继续模拟。

## 原型范围

- 数值采用可调整的测试值，用于观察节奏，不视为平衡定稿。
- 金鱼已实现参考按住／松开控条的垂钓小游戏，难度、鱼的运动曲线与进度速率为测试取值；垂钓时暂停岛屿模拟。其他物种后代仍用交互收取或虾笼自动捕获，不会因收获删除亲代。
- 保留四套 9×9 规则实验场；新增 18×19 正式图按 FigJam 四表逐格转录。用户已于 2026-10-13 确认它是一张连续地图，数字表示地面高度、道具叠放其上。无数字宝箱、船格和出生点等其余实现假设仍单列于正式关记录。
- 码头先以岛边交易与单件搬运体现循环，未制作独立码头地图、航行过程及居民对话。
- 持续生成野生动物、剧情推进和长期成长尚不属于本次生态测试；测试快照用于保存与复现当前实验状态。
- 美术导入与来源以项目 `ART_SOURCES.md` 为准；资源的最终精修质量不作为玩法规则的验证依据。

最终规则边界可在 `Assets/HabitatIsland/Scripts/HabitatModel.cs` 对照，预设测试地图在 `HabitatLevels.cs`。修改规则后应同步本文件，避免文档成为另一套口径。
